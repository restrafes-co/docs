The endpoint publishes an unlock command to the access point’s Roblox location.

## Scope behavior

- `universe` publishes the command to the location’s active subscribed servers and returns without waiting for a player-specific acknowledgment.
- `player` targets a Roblox user by `robloxUserId` or `robloxUsername`. If both are supplied, `robloxUserId` takes precedence.

## Unlock duration

| Request | Applied duration |
| --- | --- |
| `unlockTime` from 2 through 60 | The supplied value |
| `unlockTime` outside that range | Returns `400` |
| Omitted with a configured access-point duration | The configured value, constrained to 2–60 seconds |
| Omitted without a configured duration | 8 seconds |

## Game-server message

XCS publishes to `xcs-location-{locationId}`. Remote unlock and Telephone Entry share this topic and are distinguished by `type`.

```json
{
  "v": 1,
  "type": "remote_unlock",
  "locationId": "598f41c2-b931-4819-89b7-555d5371314a",
  "payload": {
    "accessPointId": "76094322-c72f-4aca-bb25-4c2dc2964e37",
    "scope": "player",
    "unlockTime": 8,
    "robloxUserId": "12345",
    "requestId": "da633f7f-aa77-45ee-826f-14a46b1221c4"
  }
}
```

<ResponseField name="v" type="integer" required>
  Message schema version. Currently `1`.
</ResponseField>
<ResponseField name="type" type="string" required>
  `remote_unlock` for this message type.
</ResponseField>
<ResponseField name="locationId" type="string (UUID)" required>
  Location that owns the access point.
</ResponseField>
<ResponseField name="payload.accessPointId" type="string (UUID)" required>
  Access point to unlock.
</ResponseField>
<ResponseField name="payload.scope" type="string" required>
  `universe` or `player`.
</ResponseField>
<ResponseField name="payload.unlockTime" type="integer" required>
  Applied duration in seconds.
</ResponseField>
<ResponseField name="payload.robloxUserId" type="string">
  Target Roblox user ID for a player-scoped command.
</ResponseField>
<ResponseField name="payload.requestId" type="string (UUID)" required>
  Request identifier used by supported acknowledgment handling.
</ResponseField>

## Delivery and acknowledgment

Roblox MessagingService delivery is best-effort. The stock XCS package subscribes to the location topic and handles supported acknowledgments automatically.

A player-scoped request can return `504` when XCS does not receive an acknowledgment before the timeout. This does not prove that no server received the published message. The public integration does not expose XCS internal acknowledgment storage; see [Remote Unlock Setup](/guides/remote-unlock-setup) before implementing a custom listener.
