# Content Critique: XCS Developer Documentation

## Executive Summary

The existing XCS documentation is fundamentally broken. Nearly every page contains fabricated technical information, broken English, placeholder content, or documentation for products and endpoints that do not exist. A developer following these docs would be misled in multiple ways: installing a non-existent npm package, hitting wrong API URLs, and configuring irrelevant settings. The documentation does not describe the actual product.

This is not salvageable through incremental fixes. Every page requires a complete rewrite.

## Systemic Issues

### 1. The Documentation Describes a Different Product

Five pages reference features, configurations, and packages that do not exist:
- The `@xcs/core` npm package
- The `/v1/resources` REST endpoints
- The `https://api.xcs.dev` base URL
- The CLI tool `xcs --version`
- The JSON configuration with `mode` and `port`

This is the most severe category of problem. A developer following these instructions cannot accomplish anything with the actual product.

### 2. Broken English Throughout

Nearly every guide page contains sentences that are grammatically incorrect, incomplete, or non-idiomatic. "XCS is a tool for Roblox. It runs door access in your games." "An organization owns sites." "They state who can go in." "It shows your group sum." These read like a first draft written by a non-native speaker without review. An authoritative developer documentation site cannot have this level of prose.

### 3. ImagePlaceholder Dependency

Every single guide page imports and uses `ImagePlaceholder`, which renders a dashed gray box saying "Replace with actual screenshot." This is acceptable during initial drafting but not for published documentation. Either provide real screenshots or remove the component in favor of detailed descriptive prose.

### 4. No Architecture or Conceptual Depth

The platform overview vaguely gestures at organizations and access points but provides no coherent model of how the system works. There is no explanation of:
- The Roblox MessagingService integration
- How access rules are evaluated
- The difference between universe-scoped and player-scoped unlocks
- How API keys work vs session auth
- The polling/acknowledgment system for remote unlocks
- How the invite code system works at a protocol level

### 5. No Developer-Facing Content

Despite the word "Developer" in the project's context, the documentation:
- Has no endpoint reference that matches the real API
- Has no code examples (curl, TypeScript, Python)
- Has no authentication guide
- Has no error code reference
- Has no webhook documentation
- Has no integration guide for Roblox developers

### 6. No Error Handling Documentation

None of the existing pages document what happens when things go wrong. The API reference has no error codes. The account creation guide only mentions three troubleshooting items. The dashboard guide has two sentences about troubleshooting. A developer cannot self-serve when things break.

---

## Recommendations

1. **Delete `guides/installation.mdx`** -- its content is entirely fictional. Replace with a proper account setup guide or fold into getting-started.

2. **Delete `components/ImagePlaceholder.tsx`** -- or keep it as a draft-only utility but remove all imports from published guides. Replace with descriptive prose.

3. **Rewrite every guide** following the Diataxis framework:
   - Explanation: platform-overview (what XCS is and how it works)
   - Tutorial: getting-started (step-by-step from zero to first access point)
   - How-to: creating-an-account, linking-your-accounts, setting-up-your-organization, exploring-the-dashboard
   - Reference: api/overview, api/consumer-overview, api/remote-unlock

4. **Verify every technical claim** against the actual API before publishing:
   - Base URL: `https://api.restrafes.co/api/consumer/v1`
   - Auth: `X-API-Key` header (not Bearer)
   - Endpoints: health, ping, organizations, routines, remote-unlock

5. **Add developer-focused content**: curl examples, error codes, authentication guide, rate limits.

6. **Write documentation for the remote unlock feature** -- this is the most important API endpoint and has zero documentation.

7. **Fix the English**. Every page needs a native-speaker quality pass.

8. **Update docs.json** navigation to reflect the actual content structure.
