The server exposes tools according to your connection's OAuth scopes. Read tools require `xcs:read`. Write tools require **both** `xcs:read` and `xcs:write`. All calls also require current Pro eligibility and the applicable organization permissions.

`tools/list` returns the authoritative JSON input schemas. Inputs are strict: unknown fields are rejected. IDs must be nonempty strings up to 100 characters. Unless otherwise shown, names are trimmed and must contain 1–100 characters; descriptions allow up to 4,000 characters and accept `null` to clear them.

All list tools accept optional `limit` (integer, 1–100; default 50) and `offset` (integer, 0–100,000; default 0). They return arrays. Other tools return a resource or operation result as JSON inside MCP text content. Role permission bitfields are decimal strings. Failed tool calls return MCP `isError`; authorization failures at the HTTP boundary return HTTP errors.

Organization-level tools use the organization UUID returned by `my_organizations`. Resource IDs come from the relevant list or create tool.

## Schedule time slots

`create_schedule.tables` and `update_schedule.tables` accept 1–100 time slots. Each slot requires `startHour` and `endHour` (integers 0–23) and `startMinute` and `endMinute` (integers 0–59).

Enable at least one day using `sunday`, `monday`, `tuesday`, `wednesday`, `thursday`, `friday`, `saturday`, or `holiday1` through `holiday8`. Each day is a boolean and defaults to `false`. Start time must precede end time on the same day. Overnight time slots are not supported. Times use the organization's timezone. Holiday flags follow the organization's existing holiday configuration.

Creating a schedule requires a name of 3–32 characters and explicit time slots. Updating a schedule replaces all slots atomically when `tables` is supplied. Omit `tables` to leave the slots unchanged. System schedules are protected from update and deletion.

```json
{
  "organizationId": "ORGANIZATION_UUID",
  "name": "Weekday entry",
  "tables": [
    {
      "monday": true,
      "tuesday": true,
      "wednesday": true,
      "thursday": true,
      "friday": true,
      "startHour": 9,
      "startMinute": 0,
      "endHour": 17,
      "endMinute": 0
    }
  ]
}
```

## Permissions and operation details

- Location writes require manage-locations permission. Access-point metadata and configuration writes require manage-access-points permission. Arming requires arm-access-points permission; `AUTO` also requires a schedule from the same organization that is organization-wide or belongs to the point's location.
- Access-group tools require manage-access-groups permission. Their write tools manage metadata and schedule links. New groups are organization-wide, so their schedules must also be organization-wide.
- Schedule tools require manage-schedules permission. Member tools require manage-members permission; role listing requires manage-roles permission; event listing requires view-activity permission. Organization management permission or ownership can satisfy these management checks under XCS's permission rules.
- Resource reads and activity respect logical resource scopes. Every referenced schedule must belong to the same organization; a location-specific schedule must match the relevant location.
- `my_organization_limits` returns effective organization caps, with `null` meaning unlimited. Create tools enforce those caps using the same quota service as the website.
- `delete_location` also deletes its access points. All delete tools return `{ "deleted": true, ... }` with the affected ID.
- `remote_unlock_access_point` returns `accessPointId`, `requestId` and `expectsPollback`. Its optional `unlockTime` is 2–60 seconds. `get_remote_unlock_status` returns `pending`, `completed` or `not_found` for that access point. A delivery acknowledgement does not prove that a door opened.

## Example MCP tool call

After the normal MCP initialization handshake, a write-authorized client can call:

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "create_access_point",
    "arguments": {
      "locationId": "LOCATION_UUID",
      "name": "North Entrance",
      "type": "REGULAR"
    }
  }
}
```

Use the returned access-point ID with `get_access_point`, `update_access_point`, `update_access_point_configuration`, `set_access_point_armed`, or `delete_access_point`.
