Start with the first Hera error in server **Output**. Record the service mode, floor, door group and triggering input. For a bank, include the assigned car.

## Hera does not start

Confirm the supplied loader and `CONFIGURATION` are under the complete elevator model in `Workspace`. Check the first loader or configuration error before editing the assembly.

| Output contains | Check |
| --- | --- |
| `Hera requires CAR and FLOORS models` | Both models are direct children of the elevator. |
| `unable to find .PLATFORM` | Restore `CAR/.PLATFORM`. |
| `Floor names must use canonical integers` | Use names like `1`, `0` and `-1`. |
| `Floor numbers and LEVEL_MAIN heights must increase together` | Match the bottom-to-top order of floor numbers and stopping datums. |
| `requires LEVEL_MAIN` | Restore the landing's reference part. |
| `requires LEVEL` or `requires DOORS` | Restore the required door-group child. |
| `Unable to find the SCALE part` | Restore the scaler inside the named leaf. |
| `has an invalid value` | Check the named parameter's bounds in the [configuration reference](/hera/reference/configuration). |

If Output reports an incomplete package or product authorization failure, check the supplied loader with your provider. [Model structure](/hera/model-structure)

## An extension does not run

| Symptom | Check |
| --- | --- |
| No initialization log | Install the ModuleScript directly under the lowercase `Elevator/extensions` Folder and restart Play. |
| `Expected a table with init(controller)` | Return a table with an `init` function that receives the controller. Use dot calls. |
| Lock setup throws | Check the floor, served entrance and scope keys. Failed initialization releases the module's Hera subscriptions and acquired locks. |
| `door.open()` or `door.close()` returns false | Check service, stop or fault state, alignment, group availability, lock, nudge and obstruction. |
| Releasing a lock leaves a call rejected | Check overlapping locks and service restrictions. Register a new call with the intended source, direction and group. |
| An extension hook misses a call acknowledgement | Read the request's private callback or use the synchronous `controller.call.add` result. |

[Extension lifecycle](/hera/extensions/getting-started) · [Lock scopes](/hera/extensions/floor-lockouts)

## The car does not move

Read `getStates` and inspect `queue`, `operating`, `service`, `stop`, `outOfService` and the separate `doorStates` table. A registered call can wait for every group to reach `closed`. For a rejected call, check the destination group, source and service mode, then inspect the applicable callback or service rejection. [State and events](/hera/reference/events)

## The car stops too high or too low

For one landing, compare the center Y of `LEVEL_MAIN` to the intended center Y of `CAR/.PLATFORM` and check the sill offset. For an error that varies by direction or trip length, disable pre-opening during diagnosis, reduce `MOTOR_SPEED` temporarily, then verify directional deceleration and `LEVELING_SPEED` on the shortest and longest runs. [Motion profile](/hera/configuration/motion)

## Doors move the wrong way or too far

Check the leaf prefix, the local orientation and dimensions of `SCALE`, and the whole-number travel multiplier. `DR2` travels two scaler widths. Use an integer suffix so Hera indexes the leaf. Compare the car and landing groups and their `LEVEL` datums. [Leaf naming](/hera/model-structure#door-leaves-and-travel-distance)

## Doors stop partway or the elevator goes out of service

Use `onDoorFault` or `onMovementFault` to identify the affected cycle, then inspect server Output. Check the group hierarchy and scalers, door curve settings or the affected movement assembly. Repair the failure before restarting. XCS Resume clears the stop state only.

## Doors remain open

Check the service mode, Door Hold latch, sensor and dwell for the affected group. In normal service, press the corresponding Door Close to clear a hold. In recall, Phase II Hold or independent service, use the [service-mode sequence](/hera/operation/fire-and-independent-service).

## Sensors do not reopen the doors

Test an avatar during normal closing before nudging. Check `DOORS.SENSOR_ENABLED`, touch detection and the position of each sensor under `CAR/.DOORSENSORS/<group>`. The standard sensor targets player characters. [Reopening and nudging](/hera/operation/door-operation#sensor-reopening)

## Buttons do not register or light

| Symptom | Check |
| --- | --- |
| One car button fails | Alias, numeric floor, served group and direct `BUTTON` child. |
| Whole panel fails | `.BUTTONS` prefix and placement directly under `CAR` or the landing. |
| Hall button fails | Entrance alias and `U`, `D` or `N` fixture name. |
| Button registers but the lamp stays dark | Direct `LED*` BaseParts and their configured styles. If there are no LED parts, check `BUTTON`. |
| Lamp briefly flashes and clears | Check rejection, current-floor service or withdrawal. Use queue events to verify registration. |

[Fixture wiring](/hera/configuration/buttons)

## A special-service call is rejected

Read `command` and `reason` in `onFireServiceCommandRejected` or `onIndependentServiceCommandRejected`. Check whether recall is complete, the car is stationary, or a destination is already selected. [Rejection codes](/hera/reference/service-api#rejected-requests)

## Phase II doors reverse unexpectedly

Confirm that the server sends the release only when the operator releases or leaves the control. Match the action and group on press and release. Early release reverses the stroke. [Constant-pressure inputs](/hera/reference/service-api#held-controls)

## Independent service will not depart

Hold the car's destination button through closure of all entrances. A custom panel sends `independentServiceFloorControl` for the held input. A plain `queueAdd` using source `"car"` can be used once the doors are closed. [Independent service](/hera/operation/independent-service)

## Floor labels or arrows are wrong

Read the display text from `message.data.label.label` when present. Use numeric keys under `API.FLOOR_LABELS.FLOORS` and numeric door-group keys for prefixes and suffixes. Seed the initial state on connection. Use move direction for a travel arrow, queue direction for serving direction, and `indicator` or `indicatorCar` for lantern commands. [PI and lantern integration](/hera/integration/group-control-and-displays#floor-displays)

## Sound or voice does not play

Check asset permissions, asset ID, volume, audible range and the entry's enable flag. For chimes, check the timing for the player that owns playback. For voice, verify the preset, enabled cue and matching vocabulary tokens. With `user-defined`, check the clip timestamps. Hera can skip a cue while an earlier announcement is still playing. [Chimes and announcements](/hera/configuration/sound-and-voice)

## An API script receives no response

| Symptom | Check |
| --- | --- |
| No `returnStates` | Use a server Script, connect before firing, and match `data.returnId`. Retry during startup. |
| Door state missing | Read `data.doorStates` beside `data.states`. |
| `Fire()` has no result | Observe an event or use a private call callback. |
| Invalid call is silent | Set `confirm = true` on the request and pass a parented BindableEvent in `data.api`. Read `data.reason` on `api-onCallResult`. |
| Accepted call has no arrival callback | Check for a same-floor car call that handled the entrance directly. Observe the door group for its resulting state. |

[Controller API](/hera/integration/controller-api)

## XCS has no status or remote control

Check the published server and job ID, access point and location IDs, reporting settings and MessagingService credentials in the [XCS connection checklist](/hera/integration/xcs#troubleshoot-the-connection).

## Gather details for help

Include the first Output error, floor and entrance, service mode, reproduction steps and relevant Explorer hierarchy. Redact API keys and credentials from screenshots or configuration excerpts.
