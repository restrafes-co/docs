The Hera bridge posts car state over HTTPS and receives dashboard commands through Roblox MessagingService. Configure both paths on a published Roblox server with a nonempty job ID. Each path has its own enable switch.

## Prepare the XCS side

Create or select an Elevator access point at the correct organization and location. Open its **Hera connection** settings and copy the access point ID, location ID and API base URL. Status reports use the organization API key. Incoming commands use the Roblox universe and Cloud messaging credentials configured for that location. [Location messaging setup](/guides/remote-unlock-setup)

## Fill in Hera configuration

In `ServerScriptService`, create a ModuleScript named `HeraXCSSecrets` that returns the organization API key. Reference it when the server loader requires `CONFIGURATION`.

<Warning>
  Keep the key value out of the elevator model in `Workspace`.
</Warning>

```lua
XCS = {
    ELEVATOR_ID = "your-access-point-id",
    LOCATION_ID = "your-location-id",
    API_URL = "https://api.restrafes.co",
    API_KEY = require(game:GetService("ServerScriptService"):WaitForChild("HeraXCSSecrets")),
    STATUS_POLLING_ENABLED = true,
    STATUS_POLL_SECONDS = 5,
    MESSAGING_CONTROL_ENABLED = true,
},
```

`NAME.ID` identifies the car in reports. Give each car a distinct ID within its server. `XCS.ELEVATOR_ID` identifies the XCS access point. Use an HTTPS base URL without an endpoint path. If the installation only receives commands, omit the key and set `STATUS_POLLING_ENABLED = false`. [Field defaults](/hera/reference/configuration#xcs-connection)

## Start and select the server

Enable the experience's server HTTP access for reporting. Join a running server with the updated configuration and open the access point in XCS. Select that server's job ID before interpreting a report or sending a command.

## What the dashboard receives

Reports include the indicated and tracked floors, travel direction, operating and service state, queued floors, served floors, door states and the user IDs of players in the server. Hera coalesces event-triggered reports and sends at most one every two seconds. Periodic reporting defaults to five seconds and is clamped between 2 and 30 seconds.

## Remote controls

| Action | What to observe |
| --- | --- |
| Call | Registers source `"api"` with the lowest eligible, unlocked door group at the destination. |
| Open or close doors | Requests the operation for all available entrances while stationary in normal service. |
| Stop | Activates the stop state and requests call cancellation. A moving car can finish braking. |
| Resume | Clears the stop and rechecks recall and dispatch. A separate fault can still block travel. |
| Inspect | Requests a fresh state report for the selected server. Requires reporting. |

A local `onXCSCommandRejected` event identifies the rejected action. Confirm the resulting car state after issuing a dashboard command.

## Troubleshoot the connection

| Symptom | Check |
| --- | --- |
| Server missing | Published server and job ID, access point and location IDs, HTTPS URL, organization key and server HTTP access. |
| Reports work but commands fail | Messaging enable switch, location universe and Cloud messaging credentials. Look for `XCS command subscription failed` in server Output. |
| Command reaches Hera and is rejected | Selected job ID and car, current service, floor, entrance and lockouts. Read `onXCSCommandRejected`. |
