Use `Elevator/API` from a server Script or accessory. The BindableEvent is server-local. Code installed under `Elevator/extensions` can use the [extension controller](/hera/extensions/controller).

## Connect and wait for startup

A listener that joins late can miss `onReady`. Connect first and request a state snapshot with a unique `returnId`. This example works from a server Script with a model named `Elevator`.

```lua
local HttpService = game:GetService("HttpService")
local elevator = assert(workspace:WaitForChild("Elevator", 10), "Elevator missing")
local api = assert(elevator:WaitForChild("API", 10), "Hera API missing")
local id = HttpService:GenerateGUID(false)
local snapshot
local listener = api.Event:Connect(function(message)
    if message.event == "returnStates" and message.data.returnId == id then
        snapshot = message.data
    end
end)

local deadline = os.clock() + 15
repeat
    api:Fire({request = "getStates", data = {returnId = id}})
    task.wait(0.25)
until snapshot or os.clock() >= deadline
listener:Disconnect()
assert(snapshot, "Hera did not become ready")
```

## Message format

Send `{request = name, data = payload}` and listen on `api.Event` for `{event = name, data = payload}`. `api:Fire(...)` has no return value. For request-specific call results, attach a separate BindableEvent.

## Add a call

`queueAdd` requires `floor`, `doorGroup`, `direction` and `source`. Send the numeric floor and an entrance served by the car at that landing. Use direction `1` for Up, `-1` for Down or `0` for neutral. Use source `"api"` for an external integration, `"car"` for a COP input or `"landing"` for a local hall input. Pass `accessibility = true` for extended door timers.

```lua
api:Fire({
    request = "queueAdd",
    data = {floor = 2, doorGroup = 1, direction = 0, source = "api"},
})
```

### Receive completion or cancellation

On a core that advertises `snapshot.confirmsCalls == true`, set `confirm = true` on the outer request and supply a **parented BindableEvent** as `data.api`. Connect the callback before sending. This snippet continues from the startup example.

```lua
assert(snapshot.confirmsCalls == true, "This core does not confirm calls")
local reply = Instance.new("BindableEvent")
reply.Parent = elevator
local finished = false
reply.Event:Connect(function(message)
    if message.request == "api-onCallResult" then
        if message.data.success then return end
        warn("Call rejected", message.data.reason)
    elseif message.request == "api-onArrival" or message.request == "api-onCancelled" then
        print(message.request, message.data.floor)
    else
        return
    end
    finished = true
    reply:Destroy()
end)

api:Fire({
    request = "queueAdd",
    confirm = true,
    data = {floor = 2, doorGroup = 1, direction = 0, source = "api", api = reply},
})

task.delay(120, function()
    if not finished then reply:Destroy() end
end)
```

| Callback `message.request` | Meaning |
| --- | --- |
| `api-onCallResult` | `data.success` reports acceptance. A coalesced call can also set `data.duplicate`. On failure, read `data.reason`. |
| `api-onArrival` | Hera served the call. Use the door state to confirm the group is fully open. |
| `api-onCancelled` | Hera withdrew the call before service. |

An accepted same-floor `"car"` request can operate the doors directly without an arrival callback. Use a matching door-state observation if your COP integration needs confirmation. The example uses source `"api"` and disposes of the callback after its outcome or a 120-second timeout. The timeout only disposes of the listener. Use `queueRemove` to withdraw the call.

## Read current state

`snapshot.states` contains movement, queue and service state. `snapshot.doorStates` is a separate table keyed by numeric group. A state read is useful on connection and after reconnecting an accessory. Follow subsequent events for changes. [Fields and event names](/hera/reference/events)

## Remove a call

```lua
api:Fire({request = "queueRemove", data = {floor = 2, direction = 0, doorGroup = 1}})
```

Use the original floor, direction and group. Cancellation applies to the shared queue entry and notifies its registered callers with `api-onCancelled`. The car can finish braking before completing removal. Older cores can use `api-onArrival` for both service and removal, so validate against the car and entrance state on those builds.

## Lock car or hall inputs

```lua
api:Fire({
    request = "lock",
    data = {
        {source = "car", floor = 2, doorGroup = 1, enabled = true},
        {source = "hall", floor = 2, doorGroup = 1, enabled = true},
    },
})
```

This legacy request gates built-in buttons. Clear it with the same entries and `enabled = false`. Use `"hall"` for legacy button locks and `"landing"` as the source for hall-origin calls. Use an [extension lock](/hera/extensions/floor-lockouts) to cover scripted calls or withdraw queued calls.

## Other controls

| Request | Effect |
| --- | --- |
| `queueCheck` | Rechecks dispatch. |
| `riotService` | With `data.enabled = true`, rejects new ordinary calls **to** `MAIN.PRIMARY_FLOOR`. |
| `playerWelds` | Uses `data.status` to request passenger attachment or release. |

Use the [service-control API](/hera/reference/service-api) for recall and operator modes and the [extension door methods](/hera/extensions/controller#doors) for normal-service door commands.
