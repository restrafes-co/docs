Use the names and paths below when building or copying an assembly. Leading dots are part of the instance names. Restart Play after changing the hierarchy.

## Elevator root

The elevator model contains these objects:

| Object | Purpose |
| --- | --- |
| Supplied loader | Starts Hera. |
| `CONFIGURATION` | Contains the car's settings. |
| `CAR` | Contains the car, its entrances, sensors, and controls. |
| `FLOORS` | Contains the landings. |
| `extensions` | Optional folder for your server-side ModuleScripts. |

## Car and floor reference parts

| Reference | Purpose |
| --- | --- |
| `CAR/.PLATFORM` | The center Y is the car's stopping datum. |
| `FLOORS/<floor>/LEVEL_MAIN` | The center Y is the car's stopping height at that landing. |
| Door group's `LEVEL` | The weld datum for that door group. |

When copying a landing, preserve the offsets between the stopping datum, weld datum, and sill.

Name floors with canonical integers such as `-1`, `0` or `3`. Numbers and `LEVEL_MAIN` heights must both increase from bottom to top. Skipped numbers are fine. Use [floor labels](/hera/configuration/indicators) for names like `L` or `P1`.

## Door groups

An entrance is available when the same numeric group exists under `.DOORS` on both the car and the landing. Groups `0` and `-1` are reserved.

With the default front and rear layout:

| Group | Entrance |
| --- | --- |
| `1` | Front |
| `2` | Rear |

A landing with only group `2` is rear-only. See [Floors and entrances](/hera/adding-floors) to add an entrance.

## Door leaves and travel distance

Place each leaf model directly under the group's `DOORS` model. Put its `SCALE` part and the parts that travel with it inside the leaf model.

| Prefix | Opening direction, relative to the door assembly | Dimension used for travel |
| --- | --- | --- |
| `DL` | Left | `SCALE.Size.X` |
| `DR` | Right | `SCALE.Size.X` |
| `DU` | Up | `SCALE.Size.Y` |
| `DD` | Down | `SCALE.Size.Y` |

The integer suffix is the travel multiplier. `DL1` travels one scaler width left and `DR2` travels two scaler widths right. Use whole-number suffixes.

For a center-opening pair, start with `DL1` and `DR1`. Keep the scaler's orientation aligned with the assembly. If a panel travels too far, check its scaler size and name before changing door speed.

## Sensors

Put touch-enabled, non-colliding sensor parts across the entrance in `CAR/.DOORSENSORS/<group>`. Match the numeric group to the door.

## Buttons and lights

| Object | Placement and purpose |
| --- | --- |
| `.BUTTONS` panel | Place directly under `CAR` or a landing. |
| `BUTTON` | A direct child of each fixture; also used as the lamp when no LED parts are present. |
| `LED` parts | Optional direct children of the fixture. Parts with names beginning with `LED` carry the lamp styles. |

See [Buttons and lights](/hera/configuration/buttons) for fixture names and examples.

## Optional counterweight

Place `COUNTERWEIGHT` beside `CAR` and give it a `.MAIN` reference. Enable its movement in [counterweight settings](/hera/configuration/motion#counterweight-and-sheaves).

## Objects Hera creates

Hera creates `API`, `LEGACY`, welds and motor objects at runtime. Install your own ModuleScripts in the permanent lowercase `extensions` folder under the elevator root. [Write an extension](/hera/extensions/getting-started)
