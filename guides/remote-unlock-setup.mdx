Configure the location’s Roblox MessagingService connection before sending remote-unlock commands.

## Prerequisites

- An XCS organization where you are an Owner or Admin
- Access to the Roblox experience in Creator Dashboard
- A running server that uses the stock XCS package or subscribes to the XCS location topic

## 1. Find the Roblox Universe ID

1. Open the [Roblox Creator Dashboard](https://create.roblox.com).
2. Select the experience.
3. Copy the Universe ID from the experience settings or its dashboard URL.

## 2. Create an Open Cloud API key

1. Open **Open Cloud > API Keys** in Creator Dashboard.
2. Create a key with MessagingService `publish` permission for the universe.
3. Copy the key and store it securely.

<Callout type="warning">
  Treat the Open Cloud key like a password. Revoke it in Creator Dashboard if it is exposed.
</Callout>

## 3. Configure XCS

1. Open the location’s **Settings > Messaging** page and link the Roblox Universe ID.
2. Configure an Open Cloud key:
   - **Organization Settings > Messaging** sets a default for linked locations without an override.
   - **Location Settings > Messaging** sets a key for one location. Select **Use organization key** to remove the override.
3. Save the settings.

XCS validates an organization key against the organization’s linked universes. A location override is validated against that location’s universe.

## 4. Receive unlock messages

The stock XCS package subscribes automatically. A custom server listener can subscribe to:

```text
xcs-location-{locationId}
```

Replace `{locationId}` with the location UUID from XCS.

```lua
local MessagingService = game:GetService("MessagingService")
local locationId = "your-location-uuid-here"
local topic = "xcs-location-" .. locationId

MessagingService:SubscribeAsync(topic, function(message)
	local data = message.Data
	if data.v ~= 1 or data.type ~= "remote_unlock" then
		return
	end

	local payload = data.payload
	local accessPointId = payload.accessPointId
	local unlockTime = payload.unlockTime

	if payload.scope == "player" then
		local robloxUserId = payload.robloxUserId
		-- Unlock for this player when present in the server.
	elseif payload.scope == "universe" then
		-- Unlock for the universe-scoped request.
	end
end)
```

Validate `v`, `type`, `accessPointId`, and scope before acting on a message. See the [Remote Unlock API](/api/remote-unlock) for the complete envelope.

## Acknowledgment support

The stock XCS package handles delivery acknowledgment for supported scoped requests. The public documentation does not define a custom acknowledgment endpoint or storage protocol, so a custom listener should not attempt to write directly to XCS internal state.

Use the stock package when the caller must receive an acknowledged player-scoped response. A custom listener can still receive MessagingService messages, but the API may return `504` when no supported acknowledgment reaches XCS.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Remote unlock returns 422">
    <p>Confirm that the location has a Universe ID and either an organization Open Cloud key or a location override with MessagingService publish permission.</p>
  </Accordion>
  <Accordion title="Remote unlock returns 502">
    <p>Confirm that the key is active, grants MessagingService publish permission, and covers the configured universe.</p>
  </Accordion>
  <Accordion title="The game server receives no message">
    <p>Confirm that a server is running and subscribed to <code>xcs-location-{'{locationId}'}</code> with the exact location UUID.</p>
  </Accordion>
  <Accordion title="A player-scoped request returns 504">
    <p>The command was published, but XCS did not receive a supported acknowledgment before the timeout. Confirm that the current stock package is running and subscribed for this location.</p>
  </Accordion>
</AccordionGroup>
